# Project README authoring template

Use this template when a real implementation exists. Replace the instructions with actual evidence; do not publish an empty project just to fill the structure.

1. **Problem statement:** one user need, inputs, outputs and explicit non-goals.
2. **Learning objectives:** three things the learner will be able to explain or implement.
3. **Prerequisites:** prior lessons and required environment; separate optional extras.
4. **Architecture:** describe data flow and responsibilities; add a diagram only if it clarifies them.
5. **Stack and dataset:** actual tested versions, data provenance, access and reuse terms.
6. **Installation:** environment creation, dependency installation and configuration. Use `.env.example` where needed.
7. **Run:** exact command, working directory and a small distributable example input.
8. **Output:** observed result with limitations. Label illustrative outputs as illustrations.
9. **Code explanation:** entry point, key functions and why the design fits the task.
10. **Validation:** test command, behavioral cases, evaluation split, baseline and actual metrics.
11. **Troubleshooting:** missing input, invalid data, dependency/API failures and recovery.
12. **Improvements:** a prioritized extension with a measurable acceptance criterion.
13. **Interview questions:** explain one design choice, one failure and one alternate approach.
14. **Further challenge:** change a constraint and ask the learner to adapt the solution.
15. **Attribution and next steps:** license notices, source links and related lesson/project.

Suggested files: README.md, requirements.txt or another justified dependency specification, src/, tests/, docs/ and data/ acquisition instructions. Add notebooks/ only when exploration adds value. Do not create empty directories.
