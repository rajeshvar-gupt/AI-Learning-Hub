# Reading a learning repository

Start with README.md: audience, prerequisites, setup, learning order and actual completion status. Follow the first published lesson. A folder name alone does not mean a module is complete.

| Item | What to look for |
|---|---|
| README | Exact run steps and expected output |
| Dependency file | What environment the author tested |
| data/ or dataset instructions | Source, access and permission to reuse |
| tests/ | Behaviors checked, not merely the number of tests |
| Issues | Known failures and planned work |
| Pull requests | Proposed changes; open does not mean released |
| Commits | History of changes and useful messages |
| License/attribution | Reuse terms and third-party exceptions |

Before running a project, inspect its entry point and dependencies. Prefer an isolated environment. Never paste credentials into a public issue. Report a bug with the command, relevant error, environment and a small nonsensitive reproduction.

For this learning hub, planned means not implemented, prepared means authored but awaiting publication, and published means available at its recorded location. “Needs repair” projects are learning/review candidates rather than guaranteed runnable examples.
