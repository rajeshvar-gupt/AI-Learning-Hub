# Contributing

Start by reading the relevant lesson, curriculum registry and open PRs. Propose one clear learning improvement at a time. Corrections, tested examples, clearer wording and accessibility improvements are welcome.

Use branches such as `docs/py-001-variables` and commits such as `docs: clarify training versus test accuracy`. Describe the problem, what changed and the checks you performed. Include source title, publisher, URL and checked date when adding a reference. Preserve attribution and upstream licenses. Submit work you have the right to contribute.

Before a PR is ready:

- Explain audience, prerequisites and learning outcome.
- Run code from the documented working directory; include error cases where meaningful.
- Distinguish actual output from illustrations and training fit from held-out results.
- Keep answers separate from assignment questions.
- Check internal links and add a next step; do not link planned folders as if they exist.
- Exclude credentials, private records, unnecessary binaries and generated caches.
- Update the registry and progress with actual status. An open PR is not a published lesson.

Do not merge your own substantial contribution without review under the initial workflow. Do not add filler or empty directories to increase activity. Discuss large moves/renames before changing the structure.
